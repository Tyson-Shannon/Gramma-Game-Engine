# Grain language (Phase 3)

Grain is a small, statically typed, GDScript-inspired language that transpiles
**ahead of time** to calls into the portable Gramma C API. There is no
interpreter shipped to a console: the generated `grain_<name>.c` file is an
ordinary C translation unit, compiled by the same toolchain as hand-written
C. It uses only C89 declarations and `/* */` comments, so the same source builds
for PC, Game Boy, NES and SMS/Game Gear.

The current compiler is v0: a real lexer, recursive-descent parser, static
type checker and C back end, wired into `gr check`, `gr build` and the asset
pipeline. See [`progress.md`](progress.md) for the change log.

## Quick start

Create a project with a `src/*.grain` file (or list files explicitly):

```toml
[project]
name = "my-game"
default_target = "pc"

[grain]
sources = ["src/game.grain"]
```

Then:

```sh
./tools/gr/gr grain --check --project my-game   # parse + typecheck only
./tools/gr/gr grain --project my-game           # write generated/<target>/*.c
./tools/gr/gr build --target pc --project my-game
./tools/gr/gr build --target gb --project my-game
```

`gr build` and `gr check` transpile automatically, so `gr grain` is mainly for
inspection and fast diagnostics. `--target` selects the output directory and
`--out DIR` writes the C somewhere else. `gr transpile` is an alias for
`gr grain`. Errors are printed as `file:line:col: error: message` with exit
status 1.

A complete, buildable example lives in `examples/grain-demo/`. Its single
`src/game.grain` file builds a moving kart, a scrolling background, an SFX and
an `on_draw()` sprite-frame handler for all four targets.

## Syntax at a glance

Blocks are brace-delimited; `;` and `:` are optional, so braces are what define
nesting. Comments are `# ...`, `// ...` and `/* ... */`.

```grain
extern tileset kart_tileset
extern map track_map

entity Kart {
    tileset: tileset = kart_tileset;
    speed: fixed = 1.5;
    jumps: int = 0;

    on_update(dt: fixed) {
        vx = 0;
        if (pad_down(P1, LEFT)) {
            vx = -fmul(speed, dt);
        }
        if (pad_pressed(P1, A)) {
            jumps += 1;
        }
        x = fclamp(x + vx, 0, itof(240));
        show(self, 0, ftoi(x), ftoi(y));
    }

    on_draw() {
        set_frame(self, 0);
    }
}

scene Race {
    background: map = track_map;
    tileset: tileset = kart_tileset;

    on_update(dt: fixed) {
        scroll(0, 0);
    }
}

game {
    title = "Grain demo";
    width = 256;
    height = 224;
    max_actors = 4;
    players = 1;
    required_buttons = [UP, LEFT, RIGHT, A];

    on_init() {
        load_scene(Race);
        spawn(Kart, itof(40), itof(80));
    }
}
```

### Declarations

- `extern <tileset|map|sfx|song> name` binds an asset generated by the pipeline
  (or a song declared in game C). Assets are emitted as `extern const ...`
  declarations in the generated file.
- `entity Name { ... }` declares a static actor pool. It **must** have a
  `tileset: tileset = <asset>;` field. Optional fields can be typed `int`,
  `fixed`, `bool`, `string`, `tileset`, `map`, `sfx`, `song` or another declared
  entity/scene type. Fields may also be declared without a type and are inferred
  from their initializer.
- `scene Name { ... }` declares scene state. Give it `background: map = ...`
  and `tileset: tileset = ...` if it uses `scroll()`; the generated `on_load()`
  then calls `gr_bg_init()`.
- `game { ... }` holds settings and handlers. Settings: `title` (string),
  `width`/`height` (positive multiples of 8), `max_actors` (1..64), `players`
  (1 or 2) and `required_buttons` (a list of button constants). Defaults are
  `GR_SCREEN_W`/`GR_SCREEN_H`, 8 actors and one player.

A program must contain exactly one `game` declaration. `grain` emits its own
`main()`, so a Grain project needs no hand-written `src/main.c`. Mixing Grain
and C translation units is still possible as long as only one of them defines
`main()`.

### Handlers

| Owner | Handlers |
|---|---|
| `entity` | `on_spawn()`, `on_update(dt: fixed)`, `on_draw()` |
| `scene` | `on_load()`, `on_unload()`, `on_update(dt: fixed)`, `on_draw()` |
| `game` | `on_init()`, `on_update()`, `on_draw()` |

Parameter annotations are required: write `on_update(dt: fixed)`, not
`on_update(dt)`. Handlers return no value; `return;` exits early. Entity
`on_draw()` handlers are registered per actor and dispatched from the generated
`game_draw()`; scene handlers are attached to the generated `gr_scene`.

### Statements and expressions

- Assignments: `=`, `+=`, `-=`, `*=`, `/=`. On `fixed` fields, `*=` and `/=`
  emit `gr_fmul()`/`gr_fdiv()`; other operators use native arithmetic. The
  checker rejects assigning to constants or mixing types (an `int` may feed a
  `fixed` and is wrapped in `gr_itof()`).
- Control flow: `if (...) { }`, `elif (...) { }`, `else { }` and
  `while (...) { }`. Conditions must be `bool`.
- Expressions: integer (`12`), fixed-point (`1.5`) and boolean (`true`,
  `false`) literals, strings, names, `self.field`, unary `-`/`not`, arithmetic
  `+ - * /`, comparisons `== != < > <= >=`, and `and`/`or`. Fixed-point
  multiplication and division become `gr_fmul()`/`gr_fdiv()`.
- Engine fields available on `self` inside entity handlers: `x`, `y`, `vx`,
  `vy` (all `fixed`) and `actor` (internal). Field names may also be used
  without the `self.` prefix inside their handler.
- Constants: `P1`, `P2`; `UP`, `DOWN`, `LEFT`, `RIGHT`, `A`, `B`, `X`, `Y`,
  `L`, `R`, `START`, `SELECT`; and `SCREEN_W`, `SCREEN_H`.

### Built-in functions

| Function | Meaning |
|---|---|
| `itof(n)`, `ftoi(x)` | convert to/from `gr_fixed` |
| `fmul(a, b)`, `fdiv(a, b)`, `fclamp(x, lo, hi)` | fixed-point helpers |
| `pad_down(p, b)`, `pad_pressed(p, b)`, `pad_released(p, b)` | input state |
| `sfx_play(id, channel)`, `music_play(song)`, `music_stop()` | audio |
| `show(entity, pal, x, y)`, `hide(entity)`, `set_frame(entity, frame)`, `set_flip(entity, x, y)` | sprites |
| `spawn(EntityType, x, y)` | spawn from that entity's static pool; returns an entity value |
| `destroy(entity)` | destroy an actor |
| `scroll(x, y)` | scroll the current scene's background (scene with `background: map` and `tileset: tileset`) |
| `load_scene(SceneType)` | switch to a declared scene |
| `request_quit()`, `quit_requested()` | exit the frame loop cleanly |

`sfx_play()` indexes declared `sfx` externs in declaration order; the compiler
emits the ID table. Builtin arity, argument types and handler signatures are
checked before any C is emitted.

## Implementation notes

- `pipeline/gramma_pipeline/grain/` contains `lexer.py`, `parser.py`,
  `typechecker.py`, `codegen.py` and shared AST/diagnostic types. There is no
  runtime component in `core/`.
- `Project.grain_sources` reads `[grain] sources` from `project.toml`, or
  auto-discovers `src/*.grain` and root `*.grain`.
- `generate()` writes `generated/<target>/grain_<stem>.c` and adds it to the
  target's `generated_sources` Meson list, alongside asset C files. The manifest
  records each source with its entity and scene names.
- Generated C is C89-compatible (`gcc -std=c89 -pedantic -Wall -Wextra
  -fsyntax-only -Icore/include` is a unit test), so cc65, GBDK-2020 and SDCC
  consume the same output as the host compiler.

## Limitations (v0)

- No local variable declarations, user-defined functions, arrays, signals,
  inheritance or generics; handlers can only use fields, parameters and
  globals.
- No `match`, `for`, exceptions or heap allocation; `while` is the only loop.
- Only `self.field` attribute access; nested object attributes are not
  supported.
- Fixed-point literals are exact decimal-to-binary expressions, not hardware
  chip-specific values; per-target fixed widths come from `gramma/target.h`.
- No VS Code extension yet; `gr grain --check` provides the same diagnostics
  from the command line.
- Music/SFX are limited to what the portable API already provides; a tracker
  score compiler is a separate Phase 3 track.
